# TrendMint — 30 天从样机到第一批真实付费用户

> 项目交付的是可以本地跑通的 MVP，不包含自动购买域名、支付账号开户、发布社交视频或保证获客。以下是可以按顺序执行的经营操作清单。

## 每日 SOP（运营者）

1. 管理员登录 `/trends`，优先查看实际来源，下载 Markdown 日报 `/api/admin/report`；演示候选不是趋势证据。
2. 从 YouTube、Google Trends、TikTok/Instagram 原生趋势、Reddit 中人工核实过去 2～7 天的新玩法：看增长、制作需求、收费竞争、版权风险、可复现程度。Instagram/TikTok 在 MVP 中走**人工录入**，不伪装成实时接口。
3. 将一个玩法加入候选，人工打分，并保存证据链接。优先评分较高且需求可变现者，但不能只凭评分下注。
4. 在 `/studio` 中由管理员「发布新模板」，配置原创 prompt、英文化 SEO slug、价格积分；先用 5～10 次模型生成验证效果。
5. 用**拥有授权**的样例内容录制 3 个短视频，观察真实完成率、用户搜索、内容创作者反馈，再开始推广。
6. 每天记录各渠道访客、生成点击、任务成功率、付款人数、退款、API账单、单客贡献额。没有付款数据时不称“已验证盈利”。

## 第 1～3 天：安装与研究

- Mac/Windows 本地运行 `python run.py`，无密钥即可测试；先打开 `/docs` 检查 API。
- 进入演示账号，测试热点雷达、创建模板、上传照片、生成 3 秒 MP4、失败返积分、下载日报。
- 建立至少 10 个候选列表。每个保留日期、关键词、原始链接、搜索需求、竞品收费、内容授权状况。
- 给 3 个候选各做一份单页竞品对比；淘汰热门视频却没有用户主动搜索制作方式的玩法。

## 第 4～7 天：验证生成质量与成本

- 在 fal.ai 申请 API 凭据，开启 `VIDEO_PROVIDER=fal`。先设低成本限额（例如每天 $5）。
- 选一条高潜力玩法：测试 20 次图片输入，按可用效果 / 身份一致性 / 失败率 / 生成时延 / 实际结算成本记表。
- 检查模型条款、商用许可、音乐/表演/肖像授权；不给自动生成内容添加未经许可的热门歌曲。
- 为第一款模板准备真实示例，重写用户可理解的描述；不要直接复制对手全部界面与素材。

## 第 8～14 天：产品可收费 Beta

- 配置美国/目标市场适用的支付主体、Stripe 测试密钥和 Webhook；实测积分包、月度订阅、续费、取消、重复 Webhook。
- 在云服务器部署演示站并绑定测试域名，设置 `APP_ENV=production`、`DEMO_MODE=false`、HTTPS、安全 COOKIE、长随机 SECRET_KEY。
- 上线前完善英文用户界面、服务条款、隐私与删除、退款和自动续费披露、邮箱验证与反机器人。
- 在真实视频 API 和 Stripe 测试模式中全链路检查，不能用演示 MP4 冒充 AI 成果。

## 第 15～21 天：首次获客

- 上线 1 个精准英文 SEO 模板页面，补充有用的制作指南（示例结果、限制、处理时长、价格、替代方案）。
- 发布 10～20 条差异明显的原创/授权视频，在平台允许的范围引导访问。避免刷量、未经授权抓取或批量垃圾关键词页面。
- 为各来源添加 `utm_source` 参数。当前仪表盘支持轻量事件计数，完善归因漏斗后再扩大投放。
- 观察真实用户的「点击→上传→生成→下载→付费」转化。记下不满意的原因并改进。

## 第 22～30 天：明确去留决策

先获得 5 个**真实**付款用户，再追求 50 人，然后才考虑扩大成本。建议设置如下决策门槛（不是市场平均指标）：

| 决策 | 执行标准（内部试验目标） | 行动 |
|---|---|---|
| 发布 | 生成成功率 ≥85% 且用户看得懂怎么做 | 开放更多真实体验 |
| 继续 | 至少 5 位非熟人真实付款，单笔贡献额为正 | 完善生成与付费转化 |
| 增长 | 获客成本低于预估客户贡献额、有可复现来源 | 再尝试第二个模板 |
| 暂停 | 长期没有制作需求、失败率高、重大版权风险 | 转向下一候选热点 |

## 成本管理

- 初期预算 **$200～400** 作为明确上限，而不是获利保证。
- 默认 6 积分/条，Spark $4.90/20 积分、Creator $9.90/50 积分、Studio $19.90/110 积分；**上线前按真实模型成本重新定价**。
- 每种模型分别测量费用，而不是直接使用 `.env` 中 `VIDEO_COST_ESTIMATE_USD` 的估计值。
- 单位贡献额 = 实际已确认收入 - 模型总账单 - 支付手续费 - 退款/争议与其他可变成本 - 可归因推广开销。免费用户消耗也计入模型总账单。
- 商业化先以一次性积分包为主。订阅需要真实可持续创作价值和清晰取消入口；不以用户忘记取消为盈利手段。

## 交付/权限边界

- 项目不会自行打开浏览器账户或绑定真实信用卡。真实 Stripe/Google/fal 密钥只写在服务端 `.env` 或云端密钥管理器，绝不发到对话或 Git 仓库。
- 在未做英文 UI、本地法律合规、邮箱验证、反滥用、退款处理与数据存储审计前，只能视为内部演示或受控 Beta。
- SEO 的自然索引并非必然；现有站点支持模板级 metadata、sitemap，生产 SEO 还应加入英文完整页面内容与搜索引擎验证。
